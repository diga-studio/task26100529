# liveswitch

直播场景切换库，由上层直播控制器调用。场景、当前播出状态与切换记录保存在内存；
素材位于本地目录，由调用方通过回调准备与释放，库本身不做音视频解码。

## 核心概念

- `SceneVersion`：一份完整场景版本（场景标识、版本号、有序素材槽位），内容由调用方提供且保持不变。
- `Hooks`：调用方提供的本地回调。`Prepare` 可阻塞或失败；`Release` 在资源无人使用时被调用，恰好一次。
- 素材缓存：同一素材标识在一次直播内只准备一次并被共享；释放后再次被使用会重新准备。

## 操作

```go
sw := liveswitch.New(liveswitch.Hooks{Prepare: prepare, Release: release})

req := sw.Submit(v)   // 接纳即取代此前尚未生效的请求；后台准备素材
err := req.Err()      // 等待结局：nil=生效，ErrSuperseded=被取代，其他=准备失败

h, err := sw.Read()   // 取得当前播出的完整版本与素材（读取期间保持可用）
h.Close()             // 结束本次读取

sw.End()              // 结束直播：等待所有准备、读取与释放完成
recs := sw.Records()  // 按生效顺序排列的切换记录（只含成功生效项）
```

## 语义保证

- 新请求一经接纳，此前尚未生效的请求即失效；失效请求即使之后准备完成也不会上播。
- 场景的所有素材准备成功后才整体生效；任一素材失败则请求失败，保留原播出场景，不产生记录。
- 每次读取获得完整一致的版本与素材；切换后旧读取可继续，新读取只能取得新版本。
- 当前场景、有效待切换请求与未结束读取使用的资源绝不释放；无使用者的成功资源恰好释放一次。
- `End` 之后不再接纳切换或新读取；`End` 返回时没有遗留资源，也不会再产生切换记录。

## 运行

```sh
go test -race ./...   # 自动化测试
go run ./example      # 调用示例（本地目录素材 + 模拟导播连续点击）
```
